# bt-manager

تطبيق محلي لإدارة شبكات MikroTik HotSpot، يبدأ بنسخة Windows محلية وواجهة عربية RTL، ويستند إلى مكتبة Go الخاصة بـRouterOS API.

> **الحالة:** نسخة تطويرية (0.1.0-dev). تم اختبار الأساس والاتصال الفعلي بالراوتر، وأضيفت إدارة HotSpot، وتوليد دفعات القسائم والطباعة التجريبية، وأساس نقطة البيع إلى فرع التطوير. يجب تشغيل `go test ./...` و`npm run build` بعد هذا التحديث؛ لا يزال محرر التصميم المتقدم، وUser Manager، والتقارير المالية الأوسع، ومثبت Windows النهائي قيد التطوير.

## مبادئ الإصدار الأول

- شبكة واحدة لكل تثبيت؛ لا تعدد مستأجرين أو اشتراكات/تراخيص مركزية في MVP.
- Go للخادم والمنطق والتكامل مع الراوتر، وReact + TypeScript + Bootstrap RTL للواجهة.
- SQLite محلية تُدار من التطبيق، دون الحاجة إلى PostgreSQL أو Docker.
- العملة الواحدة تُحدد في الإعداد الأولي، وتُقفل بعد أول معاملة مالية.
- الواجهة الأمامية لا تتصل بالراوتر ولا ترسل أوامر RouterOS خامًا.
- خادم الويب يستمع إلى `127.0.0.1` فقط في هذه المرحلة؛ لم يُفعّل وصول LAN لأن المصادقة وHTTPS لم يكتمل بناؤهما.

## المتطلبات

- Go 1.23 أو أحدث ضمن سلسلة Go 1.x متوافقة مع `go.mod`.
- Node.js LTS وnpm للواجهة أثناء التطوير والبناء فقط.
- Windows للتغليف النهائي؛ يمكن تطوير أساس Go/React واختباره أيضًا على Linux.
- راوتر MikroTik في LAN لاختبارات التكامل؛ لا يلزم لنجاح الاختبارات الوحدوية.

## تشغيل وضع التطوير

من جذر المشروع، في الطرفية الأولى:

```sh
go mod tidy
go run ./cmd/bt-manager -listen 127.0.0.1:8080
```

وفي طرفية ثانية:

```sh
cd web
npm install
npm run dev
```

افتح `http://127.0.0.1:5173`. يمرر Vite طلبات `/api` إلى خادم Go المحلي.

## الاختبارات والبناء

```sh
go test ./...
cd web
npm install
npm run typecheck
npm run build
cd ..
go build ./cmd/bt-manager
```

يبني Vite أصول الواجهة إلى `internal/ui/dist` ليتم تضمينها في ملف Go التنفيذي. بعد بناء الأصول، يستطيع الخادم عرض واجهة الويب من الحزمة نفسها دون Node.js وقت التشغيل.

## HotSpot والقسائم

- معاينة خوادم HotSpot والملفات التعريفية والمستخدمين والجلسات النشطة.
- إنشاء وتعديل وتعطيل وتفعيل وحذف حسابات HotSpot والملفات التعريفية.
- يمكن إنشاء الحساب أو القسيمة باسم مستخدم فقط دون كلمة مرور.
- إنشاء دفعات قسائم حتى 200 حساب في المرة؛ يرسل التطبيق أوامر إضافة typed إلى RouterOS ويحفظ القسائم المنشأة بنجاح في SQLite.
- استوديو طباعة مبدئي يدعم تخطيطات A4: 60 بطاقة (4×15 أو 3×20) و45 بطاقة (3×15)، وتغيير اسم الشبكة واللون وعبارة إضافية وخلفية صورة. يستخدم الطباعة إلى PDF من المتصفح.
- إذا فشل إنشاء دفعة جزئيًا، يُحفظ عدد القسائم التي سُجلت محليًا وتُعرض حالة الدفعة؛ القسائم غير المحفوظة محليًا لا تدخل في ملف الطباعة.

**مهم:** توليد الدفعة ينشئ مستخدمين فعليين على الراوتر. اختبر بعدد صغير وحساب مخصص قبل إنشاء دفعات كبيرة. الواجهة تستعمل حساب اتصال الراوتر الموجود في نموذج الاتصال، ولا تحفظ كلمة مروره في إعدادات التطبيق. إعدادات تصميم الكرت الحالية مؤقتة في جلسة الواجهة؛ الحفظ الدائم لقوالب التصميم يأتي ضمن المرحلة التالية.

## نقطة البيع (POS)

- تعريف باقات بيع محلية مرتبطة بملف HotSpot وخادم وحد استخدام زمني محددين، مع سعر ومخزون محسوب من القسائم المطابقة.
- تنفيذ البيع في معاملة SQLite واحدة: حجز القسائم، تحديث حالتها إلى «مباعة»، حفظ تفاصيل الإيصال، وتسجيل الحركة المالية.
- لا يمكن بيع القسيمة نفسها مرتين، ولا يُعتمد البيع إذا كان المخزون لا يكفي.
- سجل المبيعات والإيصالات يتضمن اسم المستخدم لكل قسيمة، اسم الباقة، الخادم، سعر الوحدة والإجمالي وطريقة الدفع.
- طرق الدفع الحالية: نقدًا، حوالة، بطاقة، وأخرى. الأسعار مسجلة بوحدات فرعية (جزء من 100) لتدعم الكسور العشرية.
- عند أول عملية بيع ناجحة تُسجَّل معاملة مالية وتُقفل العملة بحسب قاعدة إعدادات التطبيق.

**حدود النسخة الحالية:** المخزون المحلي يعتمد على القسائم التي أُنشئت من داخل التطبيق وحُفظت في قاعدة بياناته. إذا حُذفت حسابات يدويًا من الراوتر خارج التطبيق فقد يحتاج المخزون إلى تسوية يدوية أو ميزة مطابقة مستقبلية. لا توجد بعد إدارة مرتجعات أو إقفال وردية أو تقرير أرباح.

## اختبار اتصال MikroTik

من إعدادات الراوتر، فعّل خدمة API أو API-SSL للمصدر/المستخدم المخصص للاختبار، وامنع الوصول غير المطلوب باستخدام جدار الحماية. توصي الإعدادات الإنتاجية باستخدام API-SSL مع التحقق السليم من الشهادة. استخدم حسابًا محدود الصلاحيات قدر الإمكان. نقطة `/api/router/test` تنفذ قراءة معلومات النظام فقط ولا تحفظ كلمة المرور.

**تنبيه:** هذا البناء لا يستمع إلى LAN. اختبار الراوتر يتم من جهاز Windows المضيف عبر عنوان الراوتر المحلي. لن تُفتح الواجهة لأجهزة أخرى قبل إضافة المصادقة والحماية المطلوبة.

## بيانات التطبيق

تُحفظ قاعدة البيانات في مجلد الإعداد الخاص بالمستخدم، لا بجانب الملف التنفيذي. يمكن تغيير المسار عبر `BT_MANAGER_DATA_DIR` أو `-data-dir`.

## المساهمة والسلامة

- لا تضع كلمات مرور أو ملفات تصدير الراوتر أو قواعد بيانات حقيقية ضمن المستودع.
- أصلح واختبر مكتبة `routeros-api-Go` بصورة مستقلة قبل الاعتماد الإنتاجي على جميع أوامرها.
- لا تفعّل LAN binding قبل اكتمال المصادقة وHTTPS.
- عمليات توليد القسائم وإدارة حسابات HotSpot تغيّر حالة الراوتر عند الضغط على زر التنفيذ؛ لا تختبرها على دفعات كبيرة قبل التحقق من الملف التعريفي والبادئة.
